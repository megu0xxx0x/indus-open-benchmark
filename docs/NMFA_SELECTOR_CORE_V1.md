# NMFA source-free selector core V1

**Checkpoint:** 2026-08-03 02:12 JST

## Outcome

The first executable component on the path to the typed NMFA execution bundle
`E` is implemented. It closes the target-blind structural selection step over
canonical synthetic or protected inventory bytes, but it is deliberately
named a development component rather than the complete `E`.

It performs no source acquisition, network access, clock read, random draw,
file write, X parsing, Y parsing, model fitting, statistical evaluation, or
public split reporting. It cannot authorize execution and cannot establish a
reading, translation, decipherment, submission, or prize claim.

## Closed interfaces

The component packages:

- a machine-readable selector plan and exact evaluator bundle;
- an exact-const plan schema plus closed Draft 2020-12 structural-inventory
  and protected declared-assignment schemas;
- canonical JSON validation with floats and alternate encodings rejected;
- component identity from the sorted physical-original member roster, stable
  only while that frozen historical roster is unchanged;
- exact rederivation of the immutable gate's complete eligible-inventory
  projection digest and comparison with a separately supplied expected digest;
- exact lowercase-hex normalization of a declared 32-byte nonce whose origin
  is not verified here;
- exhaustive site, period, medium, and object-type tuple enumeration;
- sequentially disjoint holdout construction with the immutable V1 minima;
- universal N2 movable-stratum support over every structurally eligible tuple;
- the immutable split-ticket and primary-F hash framing;
- stable development/validation assignment by repeating
  `[development, development, validation]`; and
- an exactly reexecutable private declared assignment with no public-summary
  method, no raw nonce, and no realized-split status.

The selector retains every structurally eligible canonical tuple. It neither
deduplicates equivalent tuples nor uses N2 support to filter ticket candidates.
The candidate state is ready only for declared-nonce analysis if every tuple
passes the frozen N2 support floor. Declared nonce bytes choose the minimum
unsigned ticket digest, with canonical tuple bytes only as an impossible
hash-tie breaker. This component permits repeated calls and therefore does not
claim one-use or anti-grinding enforcement.

## Information and authority boundary

The inventory contract has no X, Y, prediction, score, target, or source-value
field. The selector receives only canonical contexts, the frozen nuisance
contract, eligibility flags, complete component membership, closure tables,
and declared predecessor/claim bindings. Protected objects suppress their
contents in `repr`, and the output remains a protected declared assignment.

Nonce syntax validation is not nonce provenance. The separately supplied
eligible-inventory digest is not proof of its own external origin. Claim
binding, provider trust, trusted time, the absence of retries, complete
source-universe and relation evidence, identifier non-grinding, full runtime
attestation, and permanent one-use consumption remain responsibilities of the
future activation wrapper.

Every analysis, derivation, and verification call accepts raw canonical
inventory bytes plus the expected eligible-inventory digest again; it never
trusts a caller-constructible “validated” handle. It rederives the exact gate
projection commitment and fails on mismatch. This proves byte consistency,
not the authenticity of the expected digest or supplied claim binding. Those
false assurances and blockers are carried in the assignment itself.

## Verification

The synthetic fixture contains 160 independent components: four disjoint
20-component holdout cells and an 80-component complement. Paired full-context
rows give all 80 holdout components N2 support. The implementation exhausts
the one eligible tuple, selects exactly one primary physical original per
component, and assigns the complement to 54 development and 26 validation
components.

The same fixture is evaluated independently through the immutable
preregistration gate's structural oracle. Tuple counts, N2 counts, computation
counters, and tuple-roster commitment agree exactly. Multi-tuple, parent-
closure, multi-member-G, ineligible-member, ticket-minimum, all four resource-
limit, forged-handle, stale-bundle, assignment-tamper, huge-integer, malformed
canonical JSON, float, extra-property, ordering, and alternate-nonce cases are
also covered.

The wheel verifier checks every bundle-bound byte, validates all schemas,
confirms the direct `jsonschema[format]` requirement and supported CPython
profile, imports from an isolated extracted wheel, loads the packaged plan,
validates a synthetic exact gate projection against a separately rederived
digest, and confirms the blocked non-operational outcome.

The reference Linux checkpoint passed 1,289 tests with 19 expected skips and
no failures or errors. Ruff, formatting, Pyright, all four isolated-wheel
verifiers, changed-file leak scanning, high/critical vulnerability and
misconfiguration scanning, and focused Python security analysis also passed.

## What remains before complete `E`

The selector is only the first component. The next implementation order is:

1. exact X side/line/token ordering, the one positive-additive model, scoring,
   and frozen length proxies;
2. exact canonical-unit Y rationals, doubled-integer midranks, exact Spearman
   state, integer square root, and round-half-even display values;
3. the deterministic HMAC counter stream, 10,000 paired bootstrap schedules,
   N1 support/Hall certificate/matching unranking and 99,999 runs, and N2
   whole-G permutations and 99,999 runs;
4. confirmatory cell/effect/control gates and exact terminal precedence;
5. prospective chronology, relation reclosure, pre-Y prediction receipts,
   metrics, nulls, and terminal handling; and
6. one final content-addressed `E` bundle followed by a separate successor
   preflight and externally authenticated activation wrapper.

Until every item is implemented and independently audited, the predecessor
preflight's `TYPED_EXECUTION_BUNDLE_UNBOUND` blocker remains correct.
